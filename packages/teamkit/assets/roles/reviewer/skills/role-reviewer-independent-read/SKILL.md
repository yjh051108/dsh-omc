# role-reviewer-independent-read

## 什么时候用
每次评审。**这条是评审与"传话"的分界线。**

## 为什么
交付方**贴的读数可能对**，但：
- 他可能跑的是**旧代码**（磁盘已改、他没重载）；
- 他可能**装置错了**（假 ctx 缺某语义 ⇒ 报了个假结果）；
- 他可能**范围不同**（他验的是"注册不抛"，而你要的判据是"条目过校验"）。

⇒ **转述 = 不可验证**。评审的价值全在"我自己跑了一遍"。

## 怎么做（最小复现套路）
1. **先要指针**：让他给出「**命令 + 期望看到什么 + 如果没看到说明什么**」。
   拿不到指针 ⇒ 直接判**证据不足**（不必自己猜他的意思）。
2. **自己跑那条命令**，把**原始输出**贴进判决（不要摘要、不要改写）。
3. **加一条他没做的独立路径**（同一事实的第二种验法）：
   - 他验 `Get-Content.Count`，你再加 `ReadAllLines.Length` 与**字节算术**；
   - 他验"文件存在"，你再加**内容指纹**（sha256）与**评审前后各测一次**（证明窗口内没被改）。
4. **做参照系校准**（证明**你的读数工具**可信）：
   自造几个已知形状的输入（含边界），看你的读法是否如预期区分它们。
   > 本项目实例：`Count=3` 无法区分「3 行+末尾 LF」与「3 行+空第 4 行」⇒
   > 必须先用 5 种已知形状校准，读数才有意义。
5. **写"残余风险"**：即使判接受，也写明**哪一处我没覆盖**（例如"交付方的回读消息在磁盘上无持久副本，
   我只做到独立复算数字，没做到溯源原始记录"）。

## 反面判据
- 我的判决里出现"交付方说…" 作为**唯一**依据。
- 我没有**自己的命令与输出**。⇒ 那不是评审，是复述。
