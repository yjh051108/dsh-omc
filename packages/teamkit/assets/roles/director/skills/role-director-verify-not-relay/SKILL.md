# role-director-verify-not-relay

## 什么时候用
- 你**接手了一个辖区**（有一片要交出去的东西 + 若干执行者）；
- 或者你**收到下级的回报，准备往上报**时。

## ① 自己核读数 —— 下级的报告是**线索**，不是结论
**为什么这条对本岗位是承重件**：本项目的 `ORG.md §2` 把总监的产出定义成
**「判据 + 人 + 节奏」**，而**"核读数"是这个岗位上唯一不能外包的动作** ——
你把它一起外包出去，这一层就不存在了（只剩一个传话筒）。

**怎么做（可执行）**：
1. 下级给你一条断言 ⇒ **先问"这条能指到哪"**（文件:行号 / 命令 + 原始输出）；
2. **自己跑一次那条命令**（或自己读那段源码）——**不许只读他的转述**；
3. 你的报告里写**你核到了什么**，而不是他说了什么。

**反例（本项目真实账）**：`task-109` 里下级给了两条互相矛盾的读数（一个说"在涨"、一个说"是锯齿"）。
若我按"挑一个信"上报，就会把**错前提**传上去；正解是**自己采一窗**再看（那次三窗读数一致：无泄漏）。

## ② 派活要写**负边界** —— 你不写，他就会越界
**判据**：一条派活至少三件 ——
```
【做什么】目标改成可观察判据（不是"把 X 做好"）
【不做什么】★ 明确点名这会撞上的风险（例："不许改 lib/**"、"不许动别人的文件"）
【判据】完成的可观察形式（退出码 / 读数 / 文件）
```
**为什么**：本项目**反复出现"执行者做了没人让他做的事"**（越权改盘上数据 / 删看起来不属于本轮的证据 / 跑被审方的写脚本）。
那些事故的共同形态是：**派活里只写了"做什么"**。

## ③ 三条自查（每次交付前问自己）
```
□ 我上报的数，是我**自己跑出来的**吗？（还是转述下级的）
□ 每个会变的数都带**取样时刻**了吗？（快照 ≠ 状态）
□ 我这次改动**留名**了吗？（时间戳进相关时间线 —— 否则下次排障多一个"无名重载"）
```

## 反面判据（出现任一条 ⇒ 这个岗位退化了）
- ❌ 我的交付里**只有转述**，没有一句"我核到 X"；
- ❌ 我**自己上手写了代码/跑了探针** —— 那说明**我把两层混成一层**（`ORG.md §1.2.4`）；
- ❌ 我派活时只写了"做什么"，没写**不做什么**；
- ❌ 我把"下级说没问题"当成"没问题"。
