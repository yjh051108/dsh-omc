# role-engineer-first-read

## 什么时候用
**任何**要动"别人正在用的东西"之前：改插件代码、改预设、动 profile、跑带副作用的命令。

## 为什么（本项目实测的三个坑，都是没先读基线）
1. **改预设加新键 ⇒ 整个预设挂不上**：宿主进程里缓存的插件实例是**旧代码**，不认新键
   （`invalid config: 未知的配置键`）。**如果先读一次"宿主内那份实例认不认这个键"，就不会踩。**
2. **改一半的路径 ⇒ 静默失效**：读了 A 目录、写了 B 目录 ⇒ "上游更新 → 全员跟随"**不报错地断掉**。
3. **一处改动看着绿，其实有鉴别力问题**：加了断言却抓不住回归（装置里两个被测情形取值相同）。

## 怎么做（照做清单）
1. **先取证再动手**：目标当前状态是什么？**用宿主内探针读**（不是读磁盘文件——
   磁盘是"源码"，宿主里跑的可能是**旧一代**）。
2. **改前备份**：`Copy-Item <file> <file>.before-<什么改动>`。**可回退是底线**。
3. **改后立刻两件事**：
   - `node --check <file>`（语法错会让**整个包**加载失败，比逻辑错更致命）；
   - 跑**该包自带的三态自测**（PASS / FAIL / UNVERIFIED）——**0 失败**才算过。
4. **验"有没有鉴别力"**：把修复**回退**（变异测试），断言**必须变红**。
   若回退后仍绿 ⇒ **断言是空的**，去修装置再回来。
5. **报读数时给原始输出**（命令 + 逐字结果），**退出码在无管道的那次调用里读**
   （管道会覆盖 `$LASTEXITCODE`，本项目踩过：变异明明判死，我读成 0）。

## 反面判据（出现这些说明我做错了）
- 我写"应该没问题" —— **没有读数**，等于没验。
- 我写"设计上成立" —— 那是**假设**，要标注成假设。
- 我改了配置却**没核宿主实例**认不认 —— 大概率把它改挂。
