# principles/ —— 自演化位（对应原版每人的 `work_principles.md`）

原版 OMC 里，教练一个员工一次，指导会被写成 `employees/<id>/work_principles.md`，
**此后每次任务都注入上下文** —— 这是"组织会学习"的真正机制（`coaching.md` 全文）。

这里的对应物：`talents/principles/<talent-name>.md`。
- **首次复盘时创建**，不是预填空文件；
- 内容只写**增量的工作原则**（"这类活在这个项目里要怎么做"），不写流水账；
- **上岗材料必须带上它**（`teamkit-assemble` §6）：`talents/<name>.md` + `principles/<name>.md` + 任务卡；
- 一个原则只有在**下一次真的改变行为**时才算生效 —— 所以要能指到具体的做法差异。
- **成长只有两轴**（委托方 2026-09-12 裁定）：① **垂直深度** —— 在自己的领域做到最棒；② **交接质量** ——
  懂得跟对应的人交接（谁接 / 接什么 / 什么时候算接住）。**没有"晋升"这条轴**；**AI 没有欲望**，
  它的导向是「把该完成的完成 + 和别人建立良好沟通」，**不是往上爬**。见 `runs/005-role-skills/GROWTH.md`。
  ⇒ 写进本目录的原则，应当能指到**这两轴之一**；指不到的多半是流水账。

命名：与 `talents/<name>.md` 同名，扩展名 `.md`。例：`principles/reviewer.md`。
