# 开会（多角色同步对齐）

## 什么时候值得开
| 开 | 不开 |
|---|---|
| 两条线对**同一事实**说法冲突 | 只是通知 → 一条 `send_message` 就够 |
| 要当场把**口径**统一（接口 / 术语 / 边界） | 一个人跑一圈就能定 → 直接定 |
| 多人**共同决策**，且要留下可追责的记录 | 探索性讨论 → 先各自写材料，再开 |

**判据**：会议必须产出一份**别人能照着办事的东西**。产出不了就别开。

## 怎么开（五步）
1. **落盘议程**：`notes/meetings/<topic>-agenda.md`。三样必须有 ——
   要裁决的**问题**（写成 A vs B，带代价）、每个发言者的**位**（它要回答哪一栏）、**时限与字数上限**。
2. **召集**：对每个参会者 `send_message`，内容 = 议程路径 + 它的发言位 + "只答你那一栏，别复述背景"。
   > **DSH 实测**：消息**先落盘再投递**；running 的成员在**下一个 step 边界**消费；inactive 会被**冷恢复**；
   > 已 queued 就**不要再发第二遍**（重发等于加一次噪声）。
3. **收集**：用 `wait_agent` 等变化 —— 但它**没有 target**，只能等"有成员动了"，然后自己去看消息与板。
   别死等某一个人；**每次等待都必须有主**（谁、什么时候交什么）。
4. **落盘纪要**：`notes/meetings/<topic>-minutes.md`，四栏固定：
   `决议`（一句话，可执行）· `行动项`（谁 + 何时 + 交什么）· `少数意见`（谁不同意，为什么）· `未决`（升给谁）。
5. **兑现**：行动项**当场转成 `team_task_create`**，不要留在纪要里 —— 没进板子的行动项等于没发生。

> ## ★★ 没开完的会必须"散场"（2026-09-14 / R101 修的**真缺陷**）
> **委托方亲眼看到的**：「那三个人**一直在会议室里面都没出来**」。
> **根因**（一行）：面板判"会议是否进行中"的唯一信号是**有没有纪要文件** ——
> ```js
> const booked = r.minutes === null      // 没纪要 ⇒ 永远"占用中" ⇒ 参会者永远坐在里面
> ```
> 而**没人写纪要是常态**（开了没空收尾、测试会议、被打断）⇒ 一间会议室**永久占用**。
> **修法（协议层）**：议程文件超过 **45 分钟**没更新且仍无纪要 ⇒ 判为**已散会（未收尾）**，
> 面板上显示 `未收尾（已散会）`，**参会者回工位**，但**房间与参会记录不删**（那是发生过的事实）。
> **给开会的人的纪律**：**会开不完也要留一句** —— 哪怕只写"未决：X 要等 Y"。
> 写纪要**不是为了流程好看**，是因为**不写会让整间屋子一直占着**。
> ⚠️ 时间兜底只是**保险丝**，不是"可以不写纪要"的许可。

## 纪律（防"互相确认"）
- 参会者只交换**可验证事实**（路径、读数、"我看到……"），不交换"我觉得 / 应该 / 大概"；
- 主持人**不转述**：把原始证据原样转给需要的人，别加自己的解释；
- **反对意见必须进纪要**。全员同意的会议要么议题太软，要么有人在客气 ——
  后者是这个系统**最容易骗过自己**的地方。

## 反模式
- 会议当同步器（大家轮流报进度）→ 那是日报，不是会议；
- 没有议程就开 → 变成聊天；
- 开完不留行动项 → 下次还得再开一遍；
- 让两个人在同一条推理上互相确认 → 只要对方客气就永远通过。
