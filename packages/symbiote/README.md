## 安装（**先读这节：本包有两种装法，且【不带 `dsh.bundle`】会决定你选哪种**）

### ⚠️ 关键前提：本包**不带 `dsh.bundle` 声明**

```
本包 `package.json` **没有** `dsh.bundle` 字段。
⇒ ★ 后果：**走"装配成 profile bundle"那条路 ⇒ 不会激活**（不是报错，是**不生效**）。
⇒ ⇒ ★ 请走【方式 A】的**注入**路径。
```

### 方式 A：Release 包（推荐，免构建）

```
从 Releases 下载 `dsh-external-dsh-symbiote-0.0.1.tgz` ⇒ 解压得到一个**含 lib/ 的目录**，然后：
  # 运行时注入（免重启）—— ★ 本包推荐这条
  # 对 AI 说：dev_inject_plugin <解压目录>
```
> ★ **为什么推荐这条**：本包 `.gitignore` **排除了 `lib/`** ⇒ 直接 clone 拿到的是**源码、没有可运行的产物**
> ⇒ 而 `scripts/build.mjs` 需要 DSH【源码】检出 ⇒ **陌生人做不到** ⇒ 所以走 Release 包（**免构建**）。

### 方式 B：git（**需要先构建出 `lib/`**）

```bash
git clone https://github.com/yjh051108/dsh-symbiote.git
node scripts/build.mjs        # ★ 纯 ESM：把 src/*.js 复制到 lib/（不需要 DSH 源码检出）
# 然后注入：dev_inject_plugin <clone 下来的目录>
```
> ⚠️ **本 README 旧版把构建写成 `bash scripts/build.sh`** —— ★ **那是错的**（本包没有 `build.sh`）。
> 实际是 **`node scripts/build.mjs`**，且它**不需要 DSH 源码检出**（只做 `src → lib` 复制）。
> ★ 已按实测改正。
