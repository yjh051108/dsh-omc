# 周报：怎么复盘（**教你怎么开，不搬我们的流水**）

> **委托方原话**：「中间怎么运营，看他们开**周报**什么的」
> ⚠️ **"看他们开周报" ≠ 把我们的流水给别人** ——
> **这份文档教你"周报该记什么、为什么这么记"**，用我们踩过的坑当例子。

---

## 1. 周报的**唯一目的**：把一次踩坑，变成一条**不会再犯**的制度

```
❌ 不是"汇报我做了什么"（那是流水）
✅ 是"我们改了哪一条规矩，从此这类事不会再发生"
```
**⇒ 判据（写完当场问）**：
```
「这份周报里，**哪一条能拦住下一次**？」
  ⇒ 一条都没有 ⇒ **这份周报不合格**（它只是流水）
```

---

## 2. 周报的四个格子（**照这个结构写，别自创**）

### 格子 ① · **发生了什么**（三行以内）

```
· 现象（可观察的）：例"用户连续两次报：重启后接不上"
· 影响面：谁受影响、影响多久
· ⚠️ **只写事实，不写解释**（解释放格子②）
```
**⇒ 反例（我们真写错过）**：
```
❌ "因为内存不够所以重启了"  ← 这是**结论**，不是现象
✅ "重启 3 次，退出码全是 130（被要求退出），不是崩溃"  ← 这是**现象**
```

### 格子 ② · **根因**（**必须有读数或指针**）

```
· 每个"因为"后面：要么给读数，要么指向一份能查的记录
· ⚠️ **不许写"我觉得是"** —— 拿不到就写「未获取」+ 列试过哪些入口
```
**⇒ 判据**：「这个根因，**另一个人**能照着我给的指针复核一遍吗？」

### 格子 ③ · ★★ **改了什么制度**（**这份周报的价值全在这**）

```
每条改动的形状必须是：
   「**原来说法** → **改成什么** → **它会在哪里红**」
```
**⇒ 三态（**不许含糊**）**：
```
· **能红的断言** ⇒ ✅ 这是**机制**（写清断言 id / 文件行）
· **只有文本**   ⇒ ⚠️ 这是**备忘** ⇒ ★ **必须显式标注"备忘"**（不许冒充机制）
· **拿不到**     ⇒ ⬜ 写「未获取」+ 为什么
```
**⇒ 一条硬判据（本公司用事故换来的）**：
```
★ **每条新规矩必须同时给出：它要拦的那个真实事故 + 一条会红的断言。**
  ⇒ 拦不住的 ⇒ **只能算备忘**。
```
**⇒ 为什么这条这么硬**（现场）：
```
本公司写过一条"管理者不再动手"的自我约束 ⇒ **它一次都没拦住人**；
真正拦住人的全是**自动断言**与**宿主硬拦**。
⇒ ★ **"文本增长 ≠ 约束增长"** —— 这是实测，不是修辞。
```

### 格子 ④ · ★★ **行动项**（**五要素齐全**）

```
每条行动项必须有：
  ① **负责人**（具名，不许写"团队"）
  ② **可验证的动作**（不是"加强意识"）
  ③ **可量的结果**（数字或判据）
  ④ **进了板子**（没进板 = 不存在 —— 判据："有人会去认领一个只写在聊天里的任务吗？"）
  ⑤ **期限**
⇒ ★★ 并加一条**合格线**：
   **「这次复盘的行动项里，至少有一条是"减少人工动作"的」**
   （删一条规矩 / 让机器替人做一步）
   ⇒ 只有"加约束"没有"减动作" ⇒ **不算合格复盘**
```
**⇒ 为什么加这条**：**制度应当"减负"，不是"加锁"**（见 [`WHY.md`](WHY.md) §2）。
一条只增加步骤、不减少错误的规矩，是**枷锁**。

## 4. **反例集**（我们真写错过的，**照抄这些错=白开周报**）

| 反例 | 为什么错 | 正确形态 |
|---|---|---|
| **只写流水**（做了什么、开了几个会） | 没有"改了什么制度" ⇒ **下周还会犯** | 聚焦格子③：一条能拦住的改动 |
| **把结论当现象**（"因为内存不足"） | 那是判断，不是观察 ⇒ **根因会跟着错** | 现象写"退出码 130、非崩溃" |
| **行动项写"加强意识"** | 不可验证、无人名、无期限 ⇒ **下周一模一样** | 改成"删掉 X 条规矩 / 加一条会红的断言" |
| **只加约束、不减动作** | 那是**加锁** ⇒ 制度越来越重 | ★ 至少一条是"减少人工动作" |
| **拿一段时间的两个数直接比** | 会变的东西**必须带时刻**（同一现象不同时刻的数不可比） | 记"哪个时刻、什么条件下" |
| **报"零/没有"却不写搜索范围** | 无法复核 ⇒ 别人会以为是事实 | 写"我搜了哪些词、哪些目录" |
| **"我觉得没问题"** | 不是读数 | 写「未获取」+ 试过的入口 |

## 5. 我们自己的**一次真实复盘**（当例子读）

```
【现象】用户报："重启之后没法续接"（连续两轮）
【根因】
  · 「所有东西都中断了」—— 实测：板**没丢**（111 条任务完整、每条都有负责人）
    ⇒ 真正断的是**成员的会话**，不是数据
  · 目标（goal）重启后变"未武装" ⇒ **那是底座故意设计**（防无人授权自动续跑）
  ⇒ 修正了用户体感的归因：**不是"数据丢了"，是"人没了 + 目标要重新打开"**
【改了什么制度】
  | 原来说法 | 改成 | 会在哪里红 |
  |---|---|---|
  | "重启后应该能恢复" | 分清**数据**（不丢）与**人**（会断） | 板恢复判据（条数/状态一致） |
  | "看到 inactive 就是没人了" | **inactive 是兜底值** ⇒ 要配"日志在不在动" | 孤儿巡检的三态输出 |
  | "目标会自己恢复" | 明说：**需要一次显式 resume**（那是设计） | 状态里显示"未武装" |
【行动项】其中一条：**把"叫一次"做成命令的输出三态**（active / 可唤醒 / 叫不动）
  ⇒ ★ **这条是"减少人工动作"**（省掉人工点名）
【未获取】"谁发的退出信号" ⇒ 试了 6 类入口，仍未知
【一句话】★ **"技术上能恢复" ≠ "用户看到续接了"** —— 结论对，不等于效果到。
```

## 6. 未获取

```
· 「开周报」的**外部用户**实践 ⇒ **未获取**（还没有外部用户）
· 我们自己的**周报频率** ⇒ **未获取**：我们实际是"按事件复盘"（出事就复盘），
  **不是固定周期** ⇒ 这份文档给的是**结构**，不是节奏
  ⚠️ **若你要固定周期**：建议**每周一次 + 出事随时加一次**（"周报"与"事故复盘"用同一套结构）
```
