## 一 · 装法（**一条命令**）

```bash
git clone https://github.com/yjh051108/dsh-omc
cd dsh-omc
./install.sh          # Windows: .\install.ps1
```

**它装了什么**——★ **公司相关的 3 项**（**仓里只有这些**）：

| 包 | 作用 |
|---|---|
| `packages/teamkit` | **公司层本体**：角色档 / 技能 / 组织层 / 指南 |
| `packages/org-panel` | **看得见公司**：侧边栏「办公室」（★ **装完要刷新页面**） |
| `docs/company/` | **怎么开公司**：方法论（**先读 `INDEX.md`**） |

**装完两步**（别漏）：
```
① 新开一个会话 ⇒ 预设选 `omc`（**已开着的会话看不到新预设**）
② ★ 装了 `org-panel` ⇒ **刷新页面**（它是 `dsh.client` ⇒ 不刷新看不到「办公室」）
```

> ⚠️ **依赖**：`install.sh` 还会装**可选依赖**（`super-injector` 运行时注入 · `engram-relay` 记忆层）——
> 它们**不属于公司**（**是通用基础设施**）⇒ **从各自的仓装**，**但用户仍只敲一条命令**。

## 二 · 已知限制（**诚实 · 逐条带读数**）

### 2.1 成员「只增不删」
```
★ **roster 没有任何移除方法**（`roster.d.ts:47-97` 只有 9 个方法）·
  journal **没有成员移除事件** · `stopTeammates` **只停会话、不释放名额**
★ ⚠️ **更狠的一层**：**`phase='failed'` 的成员照样占名额、照样占名字**，
  但**它发消息找不到**、**连 Team 身份都没了** ⇒ ★★ **一个"看得见、用不了、删不掉"的僵尸**
⇒ **"招错一个人" = 永久少一个名额**（**唯一"重开一局"= 新开 Lead 会话**）
```
### 2.2 `RULES.yml` 是**协议，不是机制**
```
★ **它没有强制点** —— 治理规则靠人读、靠评审门
⇒ ⚠️ **例外**：**"评审门"已经是真机制**（把"评审"建成任务 + 下游 `blocked_by` 它 ⇒
  **下游 `claim` 会被宿主硬拒**）
```
### 2.3 装了但"没反应"的两种死法
```
① ☠️ **宿主起不来**（坏 client 插件在 registry ⇒ 恢复 ⇒ apply 失败）
② 😶 **静默不激活**（有 `dsh.client` 却**没进 `bundles`** 且**无 `dsh.bundle`**）
⇒ ★ **本仓两个包（`teamkit` · `org-panel`）都有 `dsh.bundle`** ⇒ **装上就生效** ✅
  （`org-panel` 另有一条：**装完刷新页面**）
⇒ ★★ **而不在本仓的那几件**（`tool-output-guard` / `issue-watch` / `model-fit` /
  `web-tools` / `symbiote`）⇒ **见它们各自的仓的 README**（其中 `issue-watch`/`model-fit`/`symbiote`
  **没有** `dsh.bundle` ⇒ 那几件要走**注入**路径）
```
### 2.4 「模型单步执行最优」那套**不在这个仓**
```
★ `model-fit` · `symbiote`（以及 `issue-watch`/`tool-output-guard`/`web-tools`）
  ⇒ **它们不属于 OMC**（**另一套插件**）⇒ **在它们自己的仓**
```
### 2.5 `pnpm` 是硬前置
```
★ `dsh plugin add` 把参数**转发给 profile 目录下的 pnpm** ⇒ **没它只报 `'pnpm' is not recognized`**
  ⇒ **看不出是缺前置** ⇒ 修：`npm i -g pnpm`
```
