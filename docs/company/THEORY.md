## 0. 一句话结论

> **AI 公司的特殊之处只有一个：生产力（AI 的能力）与生产关系（我们的制度）之间的错配方式，与人相反。**
> 人的公司里，**制度常常是在压制人的"歪心思"**（偷懒、隐瞒、搭便车）；
> AI 的**遵从性高、没有歪心思** —— 所以照搬人类公司制度，**是在为一群不会犯那个错的对象，付那个成本**。
> ⇒ **我们的制度应当"减负"，而不是"加锁"。**
> 这一条，把我们最近 6 次事故的教训串成了一条线（见 §4）。

## 1. 生产力决定生产关系 —— 我们的"生产力"到底是什么

马克思：**生产力决定生产关系，生产关系要适应生产力的性质**。
⇒ 先要说清：**我们的生产力是什么**。答错这一步，后面全错。

| 我们以为的生产力 | 实际的生产力（有读数） |
|---|---|
| "agent 多" | ❌ **不是** —— 编制上限已到 100，但**再多也不会更产出** |
| "token/算力" | ⚠️ **是成本项**，不是生产力（委托方原话：「**你们都是花 token 的**」） |
| **★ 上下文质量 + 成员垂直专长** | ✅ **是** —— 委托方原话：「**AI 的注意力和上下文都是很宝贵的资源**」「**每个人干的越专越好**」 |

**⇒ 由此推出一条硬判据（我们已在用，现在给它理论位置）**：
```
上下文 = 生产力 ⇒ 任何**占用管理者上下文却不产生价值**的动作 = **浪费生产力**
  ⇒ 这正是 D-7 的根据：**"转发不产生价值"**（信息在中间被压缩一次）
  ⇒ 也是 D-1 的根据：**"为产出而读数"占上下文且产出应由执行者做** ⇒ 不许
```
**可核读数（我们自己的例子）**：
- `task-57`、`task-69` 的**死锁**都源于"owner 空 + 下游 blocked_by" ⇒ 我巡逻才发现。
  ⇒ **那不是"人懒"，是生产关系（任务板语义）与生产力（无人自动接手）不匹配**。
- 我（COO）**唯一被证明有效的动作**是：**独立复核 + 裁定 + 排节奏** ——
  三次事故里我**没有改过一行代码**，但事故闭环了。⇒ **"只管"确实能产出**（这是"制度也是生产力"的实证）。

## 3. 各尽所能 + 协作创造新的生产力 —— 但 AI 的"协作成本"与人相反

**马克思：协作不仅提高个人生产力，而且"创造了一种新的生产力"**（《资本论》第一卷第十一章）。
**⇒ 分工与协作在原理上没错。**但**适配 AI 时要改一个参数**：

```
人类组织：协作的成本 ≈ 沟通时间；换来的是**知识互补** ⇒ 净收益常为正
AI 组织：协作的成本 = **重新载入上下文**（我们最贵的资源）；
         而 AI 的"知识"大多**可从同一个底座直接读到** ⇒ **互补性远小于人**
```
⇒ **推论（重要）**：
```
· AI 组织的**最优分工比人类更"浅"、更"窄"**（`MANAGEMENT.md §四` 已写：span of control 应比人类更窄）
· 但**不能不分**：因为**上下文是稀缺的** ⇒ 分是为了**保护每人的上下文**，不是为了"汇报关系"
  ⇒ ★ 这是委托方那句的关键：「公司的约束主要**为了方便让 AI 专注到对应的垂直领域上去成长**」
     ⇒ **约束的目的是"专注"，不是"控制"**
```
**⚠️ 由此否决一个我们差点做错的事**：
```
委托方要"谁归谁管刻进成员脑子" ⇒ 若把它做成"**汇报关系树**"，就是**照搬人类公司**。
⇒ 正确形态：**编制卡 = 我的垂直领域 + 我该向谁报 + 我手下有谁**
  —— 目的是让成员**知道边界、少被打扰**，**不是**增加汇报动作。
⇒ 判据（已写死）：**未声明的成员必须显示"未声明"，不许编一个上级**（假归属比没有更坏）。
```
> ★ **CEO 已据此裁定 `task-87` 收缩**（原话：「我给的选项 2 **维护归属表**现在应当降级或砍掉
> —— 因为它的价值是"汇报关系"，而 AI 不需要」）：
> ```
> ✅ 只做：每个人自己的编制卡进**它自己的上下文**
> ❌ 不做：全局归属表（那是给管理者看的，不是给 AI 用的）
> ❌ 不做：汇报关系树（**没有对应的行为需要它**）
> ```
> ⇒ **这是本文件第一条"已经改变了决策"的推论**（不只停在纸面）。

## 5. 生产力 > 成本 —— 把它变成每件事都要回答的问题

**⇒ 我据此在协调台账里加一列「产出」（CEO 已要求，已执行）**：**没有可交付物的条目，不该做。**
**⇒ 但要点破一个陷阱**：`token` 不是唯一的成本，**上下文占用也是成本**（§1）。
⇒ 所以判据应是两问，不是一问：
```
① 这件事**产出什么可交付物**？（文件 / 读数 / 通过的判据 / 别人能用的东西）
② 它**占用谁的上下文**？占用 CEO/总监的 ⇒ 更贵 ⇒ 门槛更高
```

· COO：**没改过一行代码**，但三次事故闭环了（定位 → 裁定 → 派人 → 独立验收）
  ⇒ 它的产出 = 判据（"4 代公式"那类根因）+ 人（派谁）+ 节奏（串行/死锁）

  （"全宿主生效"被真读数推翻 ⇒ 我据此撤回了一条裁定）
  ⇒ 它的产出也**不是"写出多少代码"**，而是**让错误的结论下不去**

  我写代码/跑探针的那些轮，出了 3 起事故（P0 板 / 日志损坏 / 红叉误报）
⇒ **结论（可核）**：**在这家公司里，"产出"与"敲命令"是负相关的。**
```
**⇒ 为什么（用 §1 的生产力定义）**：

⇒ 且我还把"上下文"变成了"产出的瓶颈"：**我一旦成为关键路径，全公司等我**
  （事实：我修板那 31 分钟，全公司的板都不可读 —— 那就是"CEO 成了单点故障"）
```

### 9.3 **24 小时运营**（`ORG.md §0.3`）= 什么？

委托方原话：「**除非这个插件完全做完了**，不然公司可以 **24 小时运营**」「**不要来找我问事情**」。

**我把它翻译成可执行的**（这是我这轮最要紧的落地）：
```
【不等 CEO 的三种情形 → 各自的正确动作】
① 有明确判据的事      ⇒ **谁 owner 谁裁**，不问任何人
② 跨域/协调的事        ⇒ **COO 裁**（它是唯一接口，`D-7`）
③ 卡住但上级不在        ⇒ **按 `D-7` 例外④ 直达上一层，但必须带"我试过什么"**
   ⚠️ 例外④ 的判据不是"我很急"，是"**上级确实不在了**"（本会话真实发生过：
      `product-director` 失败 ⇒ 我授权 `panel-fixer` 直接报我）
【只有三类事后必报 CEO】（`ORG.md §0.3`）
  · 花预算 / 开人 / 设别人任务的依赖（Lead-only 动作）
  · 不可逆动作（开源 / 删数据 / 改宿主）
  · 跨辖区且 COO 裁不了的分歧
⇒ ★ **"想确认一下"不在三类里** —— 那是在把决策成本转嫁给 CEO，**直接违背 §0**
```
⚠️ **一条必要的边界（防止"24 小时"变成"没人管"）**：
```
· "24 小时运营" ≠ "无人复核" ⇒ `D-6` 仍在：**验收权在总监，点击权在 owner**
· "不问 CEO" ≠ "不落盘" ⇒ 所有裁定必须**进板子或进 `notes/`**
  （依据：COO 那句「**没人会去 claim 一个只写在聊天里的任务**」）
```
