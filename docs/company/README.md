## 为什么单独一个仓（**不并进插件**）

```
`dsh-teamkit` = **装的东西**（插件：机制 + 工具 + 角色档）
`dsh-company` = **读的东西**（方法论：为什么这么设计、怎么开、怎么运营）

⇒ 混在一个仓里 ⇒ 陌生人打开会困惑"我到底装什么" ⇒ **违反"越方便别人装越好"**。
```
**判据**：**一个没参与过的人**，读完这个仓 + 装完 `dsh-teamkit` + 选 `omc` 预设
⇒ **能开出一家像样的公司**，且**中间不需要问任何人**（问了 ⇒ 说明文档缺东西）。

## 一分钟版：这家公司的设计原理

**马克思：生产力决定生产关系。** 所以先答一个问题：

> **AI 公司的"生产力"到底是什么？**

```
❌ 不是"agent 多"（编制上限能到 100，再多也不会更产出）
❌ 不是 token / 算力（那是**成本项**）
✅ 是【上下文质量 + 成员的垂直专长】
```
⇒ **由此推出这家公司唯一的核心判断**：
```
★ **"占用上下文却不产生价值"的动作 = 浪费生产力** ⇒ 该砍。
```
⇒ ★★ **而 AI 公司与人的公司有一个根本差别**（这决定了整套制度的形状）：
```
人的公司里，制度常常在**压制人的"歪心思"**（偷懒、隐瞒、搭便车）；
AI 的**遵从性高、没有歪心思** ⇒ 照搬人类公司制度，
  **是在为一群不会犯那个错的对象，付那个成本**。
⇒ **所以这里的制度应当"减负"，而不是"加锁"。**
```
**完整的推导（含我们用过的真实事故）在 [`WHY.md`](WHY.md)** ——
**每一条结论都配一条判据，在 [`CRITERIA.md`](CRITERIA.md)。**

## 三层（委托方原话就有这三层）

```
① 开公司（建立）  —— 怎么起第一支队、怎么铺第一块板
② 运营（运行+评审）—— 怎么让"完成"不等于"被批准"、怎么不被依赖卡死
③ 周报（怎么复盘）—— 怎么把一次踩坑变成一条制度
```
> ⚠️ **"看他们开周报" ≠ 把我们的流水给别人** ——
> 这个仓**教你怎么开周报**（给模板 + 为什么这么记），**不搬我们的流水**。
